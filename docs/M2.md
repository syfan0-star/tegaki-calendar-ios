# M2 の実装結果（月ページ＋手書き＋予定の読み取り）

[M2_CONTRACT.md](M2_CONTRACT.md) の契約を実装した結果のまとめです。設計の根拠は [DESIGN.md](DESIGN.md)（§2.2・§3・§4・§8）。
ブランチ `m2`。`main` への取り込みはリード（本人）が行います。

## 1. 作ったもの

### 1.1 TegakiKit（ローカル Swift パッケージ。Foundation だけに依存）

| 製品 | 内容 |
| --- | --- |
| `DayKit` | `DayKey`（年月日だけの日付。時差に左右されない計算）、`YearMonth`（`inkPageId` = "m1-2026-10"） |
| `Holidays` | `JapaneseHolidays`（2000〜2099 年。内閣府の一覧 2000〜2027 年と一致） |
| `Layout` | `PaperSpec`（紙の寸法 lu）、`CellKey`（マスの鍵）、`LayoutEvent`（正規化した予定）、`MonthLayoutEngine.layout`（行の高さ・マス矩形・終日の帯のレーン詰め・時間指定チップ・日付見出し・当たり判定・スクロール補正） |
| `InkModel` | `InkPage` / `InkStroke` / `InkPoint`（手書きの台帳。Web 版 `model.js` と同じ merge の法則）、`InkPageCodec`（JSON ⇄ LZFSE）、`JSONValue`（未知の項目を保持して書き戻す） |
| `KitChecks` | Xcode が無い Mac で走る 264 項目の検査（実行ファイル）。CI でも走ります |

`import Layout`（または `Holidays`）が `DayKit` を再公開するので、アプリは契約どおり `Layout`・`Holidays`・`InkModel` の 3 つだけを import しています。

### 1.2 アプリ（Sources/TegakiCalendar）

| ファイル | 内容 |
| --- | --- |
| `Views/MonthPageScreen.swift` | 月ページの画面。ヘッダー（◀ 今日 ▶・「2026年10月」・表示するカレンダーのメニュー）、曜日の固定行、キャンバス、ツールバー、予定の詳細シート、「+n件」の一覧シート、初回案内 3 枚、1.5 秒デバウンスの保存、月切替前・バックグラウンド時の保存 |
| `Views/ToolbarView.swift` | ペン（6 色 × 細・中・太）、マーカー（4 色）、消しゴム、元に戻す／やり直す、「指でも書く」。選んだ色と太さは記憶 |
| `Views/EventDetailSheet.swift` | 予定の内容（題名・日時・カレンダー・場所・URL・メモ）。M2 は閲覧のみ |
| `Ink/InkCanvasView.swift` | `PKCanvasView` を紙のスクロールビューとして使い、下に `PaperView` を敷いて scroll / zoom を同期。幅ぴったりが最小倍率、最大はその 4 倍。ペンを離して 300 ms 後に行の伸び縮みを反映し、見えている行が動かないよう `scrollDelta` で補正。指タップ → 予定を開く |
| `Ink/InkLedger.swift` | 台帳 ⇄ `PKDrawing` の変換（各線は「マス相対の点列 ＋ マス左上への平行移動」）、`transform` に依存しない指紋で差分を取る、消した線は墓標、履歴は自前（最大 200。消した線を戻すときは新しい id の複製） |
| `Ink/InkTools.swift` | 道具の定義（Web 版と同じ色・太さ）と `PKInkingTool` / `PKEraserTool(.vector)` への変換 |
| `Ink/PaperView.swift` | 紙の描画（罫線・日付・今日の丸・土曜青・日曜と祝日赤・祝日名・終日の帯・時間指定チップ・「+n件」・メモ欄）。色は Web 版 `views.css` と同じ |
| `Ink/PencilInteraction.swift` | Apple Pencil のダブルタップ／スクイーズ（iPad の設定どおりにペン ⇄ 消しゴム） |
| `Calendar/EventKitService.swift` | 許可（iOS 17 のフルアクセス）、42 日分の予定の取得、終日の end を翌日 0 時（排他）に正規化、カレンダー色 → `#rrggbb`、辞退した招待は除外 |
| `Calendar/EventStoreModel.swift` | 画面用の `ObservableObject`（許可状態・予定・カレンダー・非表示カレンダーの記憶）。`.EKEventStoreChanged` を 1 秒デバウンスで購読。祝日・誕生日カレンダーは最初だけ既定で非表示 |
| `Persistence/InkPageStore.swift` | `Application Support/TegakiCalendar/ink/<pageId>.json.lzfse` にアトミック保存。壊れていたら `.bak` に退避して空ページ |

M1 のアプリ内コピー（`Calendar/DayKey.swift`・`MonthLayout.swift`・`Holidays/`・`Views/MonthGridView.swift`・`Views/EventListView.swift`・`Ink/CanvasView.swift`）は削除し、パッケージ版に置き換えました。

## 2. 確かめ方

### 2.1 GitHub Actions（Xcode 無しでも）

`m2` ブランチへの push で `build` が走り、緑なら「パッケージの検査（macOS）」「アプリのビルド（シミュレータ）」「シミュレータのテスト」がすべて通っています。Actions タブで確認できます。

テストの後、同じシミュレータでアプリを **スクリーンショットモード** で起動し、画面を撮って Actions の成果物 `screenshots`（7 日保存）に置きます（`ipad-portrait-month.png`、横向きを頼んだ `ipad-landscape-month.png`、アプリのログ `app-log.txt`）。この手順はシミュレータが不調でもジョブを失敗にしません。

スクリーンショットモード（`Sources/TegakiCalendar/Support/ScreenshotMode.swift`）は起動引数 `--screenshot-mode` があるときだけ有効です。初回案内を出さず、EventKit には一切触れず（許可も求めない）、`--screenshot-month 2026-10` の月に決まった見本の予定（20 日は時間指定 5 件で「+3件」、16 日は終日 4 件で行が伸びる、家族旅行は 9〜13 日で週をまたぐ）を入れ、「今日」は 7 日に固定、14 日のマス・20 日のチップ・メモ欄に手書きの見本（ペン・マーカー・点）をメモリ上だけで載せます（`InkPageStore` は読み書きしない）。`--screenshot-landscape` を足すと横向きを UIKit に頼みます（iPad のマルチタスク対応アプリでは聞き入れられないことがあります）。

### 2.2 この Mac（Command Line Tools だけ）

```bash
cd TegakiKit
swift build            # DayKit / Holidays / Layout / InkModel / KitChecks をビルド
swift run KitChecks    # 「KitChecks: all 264 checks passed」と出れば OK
cd ..
for f in $(find Sources Tests -name '*.swift'); do swiftc -parse -swift-version 5 "$f"; done   # 構文の確認
```

XCTest は Command Line Tools に無いので、パッケージの `swift test` とアプリのテストは CI でだけ走ります。

### 2.3 iPad で（TestFlight に入ってから）

1. 初回案内が 3 枚出ます（カレンダーのアカウント → フルアクセスの説明 → ペンと指の使い分け）。最後のボタンで iOS の許可画面が出ます。
2. 月ページに Apple Pencil で書けます。指はスクロール・ピンチ・タップ。
3. 予定の帯（終日）やチップ（時間指定）をタップすると詳細。「+n件」をタップするとその日の一覧。
4. あるマスの下の方まで書くと、その週の行だけが伸びます（他の行は動きません）。予定が増えても同じ。
5. ◀ ▶ で前後の月へ。手書きは月ごとに保存され、戻ると残っています。
6. Apple Pencil のダブルタップ（iPad の設定で「消しゴムに切り替え」などを選んでいる場合）でペン ⇄ 消しゴム。

## 3. 本人が見るもの

- ヘッダー: ◀ 今日 ▶ と「2026年10月」。許可があるときは右端にカレンダーのメニュー（表示／非表示の切り替え）。
- 許可が無いときは一行の案内（「許可する」または「設定を開く」）。
- 紙: 月曜はじまり 6 行 × 7 列、紙色 `#fffdf8`、罫線 `#e5e7eb`、今日は青い丸、土曜は青、日曜・祝日は赤（祝日名つき）、月外の日は薄く。終日の予定は色つきの帯（複数日は 1 本、週をまたぐと端が開く）、時間指定は「● 9:00 題名」のチップ（1 日 3 件まで。4 件以上は 2 件＋「+n件」）。グリッドの下にメモ欄（罫線入り）。
- ツールバー（下端）: ペン／マーカー／消しゴム、色見本、太さ（ペンのみ）、元に戻す／やり直す、「指でも書く」。

## 4. 既知の制限・確認待ち

### 4.1 契約からの小さなずれ（意図したもの）

- `DayKey` / `YearMonth` は独立した小ターゲット `DayKit` に置いた（契約が許した選択肢）。製品一覧に `DayKit` も並ぶ。
- `MonthLayoutInput` と `packAllDayLanes` に `calendar:`（既定値つき）を末尾に追加（テストを決定的にするため）。
- `InkStroke.inkStart` は `t` から導出する読み取り専用の計算プロパティ（JSON には書かない）。
- `TimedChip.timeText` は泊まりの予定の翌日側で "〜11:00"、丸一日またぐ日は ""（Web 版 `chipTime` と同じ）。
- `InkCanvasView` に契約外の `onHistoryChanged`（既定値つき）を追加。元に戻す／やり直すボタンの有効・無効に使う。
- `InkCanvasView` は月ごとに作り直す（`.id(month)`）。DESIGN §3.10 の「1 枚を使い回す」より保守的。
- 「+n件」のタップは日ページではなく、その日の予定一覧シート（日ページは M3）。日付見出しのタップは何もしない。
- 初回案内は 3 枚（DESIGN §2.10 の 4 枚ではない）。許可状態が既に決まっていれば出さない。
- DESIGN §4.2 の「5 分ごとの再取得」は未実装（前面復帰・変更通知・月切替・カレンダー表示切替で再取得）。
- アプリのテストターゲットは残し、中身を `InkLedgerTests`（PKStroke の transform ⇒ 同じ指紋、消したら墓標、戻すと新 id の複製、合成し直しで差分なし、JSON/LZFSE 往復）と `EventKitServiceTests`（終日 end の正規化、色の変換）に差し替えた。
- `MARKETING_VERSION` を 0.2.0 に上げた。

### 4.2 実機でしか確かめられないこと

- `PKCanvasView` のピンチ拡大（最小 = 画面幅 ÷ 1400、最大 = その 4 倍）と、拡大中の `contentSize` の追従。
- ペン使用中に `canvasViewDrawingDidChange` が来るかどうか（どちらでも動くように作ってある。描画の差し替えはペンを離して 300 ms 後）。
- 3 本指の取り消しジェスチャが PencilKit 側の履歴を使わないこと（`undoManager?.removeAllActions()` で無効化。もし抜けても台帳は整合）。
- 紙の文字の見え方（`max(lu, 10pt/zoom)`。チップ 20 lu の高さに収まるか）。
- 再レイアウトの遅れ・ちらつき（`onInkBoundsChanged` と `onHistoryChanged` は SwiftUI の更新中の状態変更を避けるため 1 ターン遅らせている）。
- `PaperView` は普通の `UIView.draw(_:)`。最大倍率で背の高いページだとバッキングストアが大きい（数百 MB になり得る）。問題があれば M3 で `CATiledLayer` 化か最大倍率の引き下げ。

### 4.3 動作上の注意

- 曜日の固定行は等幅 7 列。紙の幅ぴったりの倍率のときだけ列が一致する（拡大・横スクロールには追従しない）。
- 「指でも書く」がオンのときは、指のタップは線（点）になり、予定を開けない（PencilKit が先に触れを取る）。オフにすると指タップで予定が開く。
- 祝日・誕生日カレンダーの既定非表示は許可後の最初の 1 回だけ計算する。後から購読した祝日カレンダーは自動では隠れない（設定画面は M3）。
- 既知 tool の線の中にある未知のキーは書き戻さない（トップレベルの未知項目と未知 tool の線は保持する）。将来「線ごとの新しい属性」を足すときは `InkStroke` に `extra` を足す。
- 同名の予定の並び順の同点処理は Unicode の `<`（Web 版は `Intl.Collator('ja')`）。
- LZFSE の `decompress` はストリーム終端より後に余分なバイトがあると失敗扱い（自前で書いたファイルには無い）。
- iPhone の見え方は未調整（ツールバーは横スクロール、ヘッダーは狭い）。主対象は iPad。
- `testflight.yml` は Secrets 未設定のため未実行。初回は Apple Developer Program 承認後に、本人が Secrets を登録してから手動で起動する。

### 4.4 技術的な注記

- 言語モードは Swift 5・並行性チェックは minimal のまま（DESIGN §8.1）。UI の class は `@MainActor`。`DispatchQueue.main.async` の代わりに `Task { @MainActor in }` を使い、Sendable クロージャの診断に依存しない形にしてある。
- `ToolbarView` の太さの記憶は `Double`（`@AppStorage` は `CGFloat` を直接は保存できない）。
- アプリのテストターゲットは `Layout`・`InkModel` を直接リンクする（`@testable import TegakiCalendar` だけではパッケージの型を解決できないため）。
