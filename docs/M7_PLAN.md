### 1.3 データ互換の規則（1.0 の端末と新しい端末が同じ iCloud を使うとき）

本人は iPad と iPhone で使っています。片方が 1.0 のまま、もう片方が新しい版、という時期が必ずあります。**どちらの端末も、相手の手書きを消したり動かしたりしてはいけません。**

**1.0 の端末が実際にすること（コードで確認済み）**
- F1 **知らないマスの線は描かないが、消さずに残す**。`InkLedger.drawing()`（`InkLedger.swift:214-237`）はレイアウトに無いマスの線を飛ばし、指紋表にも入れないので「消された線」と見なさない。消しゴム・投げなわは画面にある線だけが対象。
- F2 **知らないページ id も、そのまま同期・保存・書き出し・取り込みする**。`SyncEngine.save`（`SyncEngine.swift:136-158`）と `mergeRemote`（`:625-652`）は id の形を見ずに merge。レコード名は pageId そのもの（`InkPageRecord.swift:32`）、ファイル名は安全な文字に置き換えるだけ（`InkPageStore.swift:30-33`）。取り込み（`AppExport.swift:127-132`）は空でない pageId なら受け付ける。
- F3 **`w-` / `d-` ページの `allday` と `allday:…` のマスの線は、読むたびに `grid` へ移す**（`BandMigration.swift:16-19, 31-53, 63-73`）。台帳（`InkLedger.swift:178, 205`）・画面（`CalendarRootScreen.swift:805, 881, 1328`）・取り込み（`AppExport.swift:131`）の全部で走る。
- F4 **同じ id の線が 2 つの形で出会うと**、t → 道具 → 色 → **マス名の辞書順で大きい方** が勝つ（`InkPage.swift:207-215`）。墓標（消した記録）は常に勝つ（`InkPage.swift:149-171`）。
- F5 1 ページの絵は、そのページのキャンバスが **丸ごと** 書き換える（`pageBinding`、`CalendarRootScreen.swift:659-664`）。
- F6 月のメモ欄の高さは `max(700, 手書きの下端 + 50)`（`MonthLayoutEngine.swift:23-26`、`PaperSpec.swift:24-25`）。
- F7 「この iPad の手書きを全て消す」は端末と iCloud の **全ページ**（知らないページも）を消す（`SyncEngine.swift:279-`）。
- F8 **1 ページの量に上限がある**。`InkPage(json:)`（`InkPage.swift:265-330`）は読むたびに、生きている線が 20,000 本（`maxStrokes`、`:14`）を超えた分を捨てる（id の辞書順で後ろのもの、`:285`）。墓標も 200,000 件（`maxTombstones`、`:15`）を超えた分を捨てる（`:277`。どれが残るかは決まっておらず、消した線が復活しうる）。自分の端末のファイルを読むときも同じで、次の保存で捨てた線がファイルからも消える。1.0 の端末はこの上限のまま読むので、新しい版で上限を上げても 1.0 の端末は切り詰める。
- F9 保存のたびにページ全体を JSON にして lzfse で圧縮し、iCloud へは丸ごとの asset で送る（`InkPageRecord.swift` の `make`）。ページが大きいほど保存と同期が重い。
- F10 組み直し（レイアウトの幾何が変わる）のたびに、全部の線から PKDrawing を作り直す（`InkCanvasView.swift:640-652`。`sameGeometry` は大きさが変われば false）。
- F11 **線の中の知らない項目は読むときに捨てる**（`InkStroke(json:)`。InkPage が残すのは、知らない最上位の項目と、知らない tool の線だけ）。merge は `compareStrokes` が 0 なら先に渡した方を選ぶ。

**守る規則（全部の版の契約に書く）**
- K-1 新しいマス名・ページ id に **`allday` で始まる名前を使わない**（F3。使うと 1.0 の端末が開いた時点で線が 0:00 の格子へ移り、F4 で `"grid"` > `"allday…"` なので iCloud 経由で新しい端末の線まで移る）。この計画で使う名前: マス `band:YYYY-MM-DD`・`band`・`focus`・`focus:01`〜`focus:12`・`focus:year`・`extra`・`plan:YYYY-MM-DD`、ページ `wb-YYYY-MM-DD`・`db-YYYY-MM-DD`・`p-YYYY-MM`、P-12 で C を選んだ場合だけ `wf-YYYY-MM-DD`（`wb-`・`wf-` は `w-` で始まらないので `BandMigration` は触らない）。
- K-2 **既存の線を同じ id のまま別のマスへ付け替えない**（F4。例: `grid` → `band:…` は b < g なので旧端末の `grid` 版が勝って元に戻る）。付け替えが要るときは新しい id で複製し、元に墓標を付ける（投げなわ移動と同じ。`InkLedger.swift:444-470`）。
- K-3 **1 つのページ id に 2 枚のキャンバスで書かない**（F5。後から書いた方が前の線を上書きする）。2 枚目のキャンバスは別のページ id にする。
- K-4 既存のマスの **意味**（マスの左上からの相対座標）を変えない。マスの **位置** は動かしてよい（線はマスについて行く。年の行の上に重点欄を足しても既存の線は動かない）。
- K-5 新しい情報は新しいマス・新しいページ・新しい tool にだけ入れる。**線（stroke）に新しい項目を足さない**（F11。1.0 との同期で、merge の順番しだいで消える）。InkPage の版 `v`（`InkPage.swift:20`）と書き出し `tegaki-app-export` v1 は上げない。
- K-6 伸びる紙の一覧（fitAll）の矩形は固定部分に限る（`ZoomPolicy.overviewSize`、`ZoomPolicy.swift:61-66`）。
- K-7 **互換テストは 1.0 のコードで走らせる**。新しい版のコードで「1.0 と同じ規則」を通すだけだと、新しい版で `BandMigration`・`InkPage`・`InkStroke(json:)`・`CellKey` を少しでも変えたとき、1.0 の動きを確かめないまま緑になる（相手の端末の手書きを消さないことを守る仕組みはこのテストしかない）。そこで:
  - 1.0 の InkModel（`BandMigration.swift`・`InkPage.swift`・`InkStroke.swift`・`PaperSpec.swift` の `CellKey` と、それらが使う補助）を、テスト専用のターゲット `TegakiKit/Tests/Compat10/` に **凍結して写す**（型名に `V10` を付け、以後は変えない）。`InkLedger.drawing()` の「レイアウトに無いマスの線を飛ばし、消された扱いにしない」判定も、純粋な関数として写す。
  - 新しい版の写真モードとテストが作ったページの JSON を `TegakiKit/Tests/Fixtures/`（golden fixture）に置き、1.0 の写し（`InkPageV10(json:)` → `BandMigrationV10.migrate` → `InkPageV10.merge` → 新しいマスの無いレイアウトでの描画対象の選び方）で読んで、線の数・座標・マス名・墓標・知らない項目が変わらないことを確かめる。KitChecks（この Mac の `swift build`）でも同じことを確かめる。
  - 写しの取り違えを見張るため、CI に 1.0 のタグ（無ければ公開ビルドのコミットに `v1.0` を付ける。作業は Claude が代行）の TegakiKit を checkout して同じ fixture を読ませるジョブを 1 本置く。
  - 書き出し → 取り込みの往復で `==` になること。
- K-8 1.0 の端末では新しい欄の手書きが **見えない（消えてはいない）**。各版の「新機能」の文に「iPad と iPhone の両方を新しい版にしてください」と 1 行入れる。
- K-9 **1 ページの線の予算**（F8・F9・F10）。
  - 1 ページの生きている線は 20,000 本未満に保つ（1.0 も同じ上限で読むので、上限を上げる意味はない）。15,000 本で「このページは手書きが多くなりました」と 1 回だけ案内し、19,000 本で新しい線を受け付けず「このページはいっぱいです」と出す。
  - KitChecks に、20,000 本を超えたページと 200,000 件を超えた墓標の往復テストを足す（何が残るかを固定する）。
  - 伸びる欄には高さの上限を設ける（月のメモ・日の `extra` は 6,000 lu。年の行 400・月の行 1,200 と同じ考え方、§2.7）。
  - 一番近づきやすいのは年のページ（1 年 = 1 ページ、372 マス＋重点欄）。1.1 で、設定の情報欄に「いちばん線の多いページと本数」を出し（端末の中だけ。送らない）、1.4 で年の重点欄を足す前に本人に数字を読んでもらう。

### 2.9 項目 11「Apple 純正カレンダーのように、タッチ操作で予定を追加・変更・削除」

#### 2.9.1 Apple 純正カレンダーの操作（調査担当が 2026-10-31 に確認）
- 日・週表示で予定を **長押しして新しい時刻へドラッグ**、または **つまみ（grab points）で長さを変える**。削除は予定をタップ → 詳細 →「Delete Event」。長押しで「Copy」→ 別の時刻を長押しで貼り付け。新規作成の公式手順は「＋」。出典: <https://support.apple.com/guide/ipad/create-and-edit-events-in-calendar-ipadafeefacf/ipados>、<https://support.apple.com/guide/iphone/create-and-edit-events-in-calendar-iph3d110f84/ios>
- 「空いた時間を長押しして新規」は昔の版の記事にはあるが、今の公式手順には無い（<https://www.macworld.com/article/223111/add-calendar-events-in-a-flash.html>）。月表示のドラッグは公式文書に記載が無い。

#### 2.9.2 今の経路

| ページ | 予定の表示 | 今のタップ |
| --- | --- | --- |
| 週 | 時間軸の箱（紙に描画。1 時間 80 lu）、固定の終日帯のバー（SwiftUI の `Button`、`AllDayBandView.swift:142`） | 箱・バー → 編集シート。帯の空き列 → 終日予定の作成、ダブルタップ → 日ページ |
| 日 | 時間軸の箱（1 時間 100 lu）、帯 | 同上（ダブルタップなし） |
| 月 | 終日バー、時刻のある予定のチップ、「+n件」 | バー・チップ → 編集。「+n件」・日付 → 日ページ |
| 年 | 終日のチップ | §2.6 |

保存は `EventKitService.update` / `delete`（`EventKitService.swift:193-217`、書き込めるカレンダーか確かめる）。`update` は `apply`（`:238-258`）で題名・場所・メモ・終日の区別を draft から書き直す（空白も削る）。予定の id は `calendarItemIdentifier@開始時刻`（`:276-280`）。繰り返しは「繰り返しの予定です」→「この回だけ」「以降すべて」「キャンセル」（`RecurrenceScopeDialog.swift:11-24`）。↶ は手書きだけが対象。紙の上の予定には VoiceOver の要素が無い（帯のバーだけ読める）。

| 案 | しくみ | 利点 | 欠点 | データ互換 | iPhone | 規模 |
| --- | --- | --- | --- | --- | --- | --- |

**推奨: A**。1.2 では手書きは増えない（「指でも書く」で長押ししたときに描きかけた点を消すだけ。消すときに墓標を書く）。予定は EventKit だけで変わる。リスクは「書く」と「動かす」の入力の取り合いと、手のひらの誤操作なので、それを 1.2 で単独に確かめる。予定の上の手書きを一緒に動かすか（P-11）は 1.2.1 で。

#### 2.9.4 基本の約束
- **Pencil は書く専用のまま**。予定の上に書けることが核なので、Pencil の長押し・ドラッグで予定は動かない（予定ツールの既存の動きは残す）。
- **入口は指の長押し**（0.5 秒。「指でも書く」オンのときは 0.7 秒。ずれ 10 pt 以内）。新しい認識器 `eventPressRecognizer`（`UILongPressGestureRecognizer`、`.direct` だけ）をキャンバスに付ける。
- **手のひらで動かさない**: Pencil が紙に触れている間と、離してから約 1.5 秒は長押しを受けない。`touch.majorRadius` が大きい触れ方（手のひら。数字は実機の記録で決める）は受けない。判断は純粋な関数 `pressAllowed(touchRadius:pencilDownAt:pencilUpAt:now:allowFinger:)` にして表でテストする。
- **状態の流れ**:
  1. 予定を指で押し続ける → **持ち上げ**（中くらいの振動、箱に影、指の横に大きく「10:15〜11:30」）。
  2. 押したまま動かす → 移動（15 分ごとに吸着、区切りごとに軽い振動）→ 離すと保存 → **選択を解く**（Apple 純正は選択が残るが、このアプリは紙に手を置いて書くので、手のひらや次のスクロールの指で動かないように解く）。トースト「予定を移動しました」＋「取り消す」。
  3. 動かさずに離す → **選択中** ＋ メニュー「開く」「複製」「削除」。選択中だけ上下に つまみ が出る。
  4. 選択中は、箱をそのままドラッグで移動（長押し不要）、つまみのドラッグで長さ、箱のタップで編集シート。変更を保存したら選択を解く。紙の他の所を指でタップ、Pencil が紙に触れる、10 秒触らない、のどれかでも解く。
- 選択中は `drawingPolicy` を一時的に `.pencilOnly` にする（「指でも書く」オンでも、選択中の指は書かない）。解いたら元に戻す。
- 「複製」は同じ時刻にコピーを作り、そのコピーを選択中にする（そのまま動かせる）。

- 日をまたぐ予定・24 時を越える予定は、第 1 段では持ち上げない（トースト「日をまたぐ予定は、編集画面で変えてください」）。

#### 2.9.6 共通の細部
- **端での自動スクロール**: 表示の上下 44 pt に入ったら縦にスクロール（端に近いほど速く）。週を拡大中は左右の端で横にも。
- **触覚**: 持ち上げで中、15 分や 1 日の区切りごとに軽、置いたときに軽、拒否はエラーの振動。
- **繰り返しの予定**: 置いた後に既存の「繰り返しの予定です」（この回だけ／以降すべて／キャンセル）。キャンセルなら元の位置に戻す。
- **動かせるかの判定** `canDrag` = `calendar.allowsContentModifications && (organizer == nil || organizer.isCurrentUser) && 日をまたがない`。今の `update` は `allowsContentModifications` しか見ない（`EventKitService.swift:196`）ので、主催者の判定は新しく足す。表でテストする。動かせない予定は持ち上げず、エラーの振動とトースト「この予定は変更できません」。長押しメニューは「開く」だけ。
- **閲覧専用**（M5）: 持ち上げ・つまみ → `blocked(.editEvent)`、空きの長押し → `blocked(.createEvent)`、メニューの「複製」→ `blocked(.createEvent)`、「削除」→ `blocked(.deleteEvent)`（既存の `GatedAction`、`CalendarRootScreen.swift:24-40`。種類は増やさない）。「開く」は今まで通り閲覧シート。
- **保存**: `EventKitService.move(eventId:start:end:span:)` を新しく作り、`startDate` と `endDate` **だけ** を変えて保存する（`apply` を通さない。`apply` を通すと、指で動かしただけで Google の予定のメモの末尾の空白などが黙って変わる）。`EventStoreModel.move` はこれを呼ぶ。再読み込みが終わるまで浮かせた絵を残し、ちらつかせない。月はドロップ後に行の高さが変わりうる（手書きはマスについて行く）。
- **id の引き直し**: 繰り返しでない予定は、動かすと id（`calendarItemIdentifier@開始時刻`）が変わる。移動の後は `calendarItemIdentifier` と新しい開始時刻で、取り消しの対象と選択を引き直す（古い id のままだと `eventNotFound` になる）。
- **ドラッグ中の再読み込み**: ドラッグ中に EventKit が変わっても（他の端末の変更・保存後の再読み込み）、箱を指の下から動かさない。`isDraggingEvent` を `applyPending` の待ちの条件に加える（ペンを使っている間の `isUsingTool` と同じ扱い、`InkCanvasView.swift:640-652`）。
- **取り消し**: 移動・長さ変更の後にトースト「予定を移動しました」「予定の時間を変えました」＋「取り消す」（**10 秒**）。押すと元の開始・終了で `move`。さらに、最後の予定の変更（移動・長さ・複製）は、ツールバーの ↶ でも 1 回だけ戻せる（最後の手書きの操作より新しいときだけ。↷ では戻さない）。「以降すべて」で変えたときはどちらも出さない（他の回を壊すおそれ）。複製は「予定を複製しました」＋「取り消す」（= コピーを消す）。削除は必ず確認（`EventEditorSheet.swift:175, 218-228` と同じ）、取り消しは無し。
- **予定の上の手書き**: 週・日の手書きは時刻の場所（`grid`）に付いているので、1.2 では予定を動かしても、その上に書いた手書きは元の時刻に残る（1.2 の「新機能」の文で説明する）。一緒に動かすかは P-11。推奨 A なら **1.2.1** で:
  - 外接矩形が箱の中に収まった手書きだけを一緒に動かす（新しい id ＋ 元に墓標。投げなわ移動と同じなので 1.0 でも動いた先に見える。K-2）。
  - 予定の保存に失敗したら手書きも動かさない（予定を先に保存し、成功してから手書きを動かす）。
  - 「以降すべて」のときも、動かすのはその回の箱の中の手書きだけ。
  - ↶ と「取り消す」は予定と手書きを一緒に戻す。
  - 月のページでは動かさない（手書きは日のマスにあり、どの予定に付いた手書きか決められない）。
- **iPhone の一覧**: 週・日とも 1 時間 ≈ 22 pt（週 0.2812 × 80 lu、日 0.2233 × 100 lu）、15 分 ≈ 5.6 pt なので、浮かぶ時刻の表示を頼りにする。12 pt より低い箱は持ち上げた間だけ 44 pt で表示（見た目だけ）。

#### 2.9.7 ほかの操作との取り合い

| 相手 | 解き方 |
| --- | --- |
| 手のひら（Pencil で書いている間） | Pencil が紙に触れている間と離して約 1.5 秒は長押しを受けない。大きな触れ方（`majorRadius`）は受けない。移動を保存したら選択を解く（§2.9.4） |
| 「指でも書く」オン（iPhone の既定） | ① 同時認識の組（`eventPressRecognizer` と `canvas.drawingGestureRecognizer`）を delegate に足す（今は「タップと描画」の組と `blockedInputRecognizer` 以外はすべて false、`InkCanvasView.swift:1174-1179`）。② 長押しの `.began` で `canvas.drawingGestureRecognizer.isEnabled` を false → true にして描きかけの線を取り消す（PencilKit の描画は指が触れた瞬間に始まり、離したときに線を確定する。取り消さないとドラッグの軌跡が 1 本の線として台帳に入り、M4C-22 の点の消去（画面 16 pt 以内・0.5 秒以内、`InkCanvasView.swift:1116-1150`）では消えない）。実機で、確定されずに捨てられることを確かめる。だめなら、指が触れた時刻より後に作られた（`creationDate`）PKStroke を、台帳に入る前に指紋で除く。③ 長押しは 0.7 秒（予定の上に書き始めて少し止まる人が、予定を持ち上げにくいように）。④ 空きの長押しは P-3 |
| 選択中のドラッグ | 選択中は `drawingPolicy` を `.pencilOnly` に一時的に切り替える（指の描画が先に始まって線が引かれないように）。箱のドラッグ用の pan は `shouldReceive` で箱への当たりを判定し、`canvas.panGestureRecognizer.require(toFail:)` にする（箱の上ではスクロールより先） |
| スクロール | 指が先に動けばスクロールが勝ち、長押しは不成立。長押しが成立したら、離すまでスクロールを止める |
| ピンチ | 持ち上げ中に 2 本目の指（`numberOfTouches` で判定）→ 移動を取り消して元へ戻す |
| ダブルタップ（週・月・年 → 日） | 時間の長さで分かれる。長押しが成立したらダブルタップは失敗扱い |
| EventKit の再読み込み | ドラッグ中は `isDraggingEvent` で待つ（§2.9.6） |
| 投げなわ・予定ツール | 長押しは無効（道具を優先） |
| Pencil | 長押しの認識器は指だけなので取り合わない。選択の解除は、`blockedInputRecognizer` と同じ形の Pencil 専用の認識器（`minimumPressDuration` 0）で行い、そのままふつうに書く |

CI では触る操作を試せないので、「指でも書く」で長押しした後に線が残らないこと、手のひらを置いても予定が動かないことは、1.2 の本人の実機確認表に入れる（§4.3）。

#### 2.9.8 読み上げ（VoiceOver）

| 3 閲覧専用のときだけ AdMob | パーソナライズしない広告、ATT なし | 少しの収入 | 「収集なし」を失う。ポリシー・規約・審査メモの書き直し、app-ads.txt のための新しい公開、Google との契約、外部送信の公表 |

**推奨: 案 1**。本人へは「無料版は、14 日間の無料試用と閲覧専用モードという形で既にあります。広告を入れると『データを集めない・広告なし』という公の約束を書き直すことになり、見込める収入より失うものの方が大きいです」と伝える。将来、自作アプリが 2 本目になったら案 2 を検討。ねらいが「利用者を増やす」だった場合は、広告ではなく無料で使える範囲の見直しとして、別に検討する（P-10）。

## 7. 検証で採らなかった指摘

第 2 版では検証の指摘をすべて読み、ほとんどを本文に入れました。次の 3 つだけは、そのままは採っていません。
- 「白紙の長さを倍率から決める（表示の高さ ÷ 倍率）」（本人の目線、§2.7）: 紙の高さ（lu）が倍率で変わると、ピンチのたびに組み直し（全部の線の作り直し、F10）が走り、端末ごとに紙の長さも変わるので採らず、もう一方の案（文言を「下に書くと、その下にさらに白紙が続きます」に直す）を採った。
- 「週の重点を 1.4 から別のページ id（`wf-`）で出し、1.5 で表示場所だけ帯へ移す」（本人の目線、§4）: 1.4 にはまだ 2 枚目のキャンバスが無く、1.5 の中心の作業（画面がページの状態の組を 2 つ持つ）を前倒しすることになるので推奨にはせず、P-12 の C として残した（表示場所を後で動かしても K-2 に触れない、という指摘は正しいので §3 の理由を直した）。
- 「年の単タップの当たりを画面上で最低 44 pt にする」（コード照合、§2.6）: 「指でも書く」がオンのときは採らない（iPhone の一覧では 44 pt がマスのほぼ全体になり、指で書いた点で日ページへ飛ぶ。本人の目線の指摘と同じ理由）。オフのときだけ採った。
