- `InkImport.Parsed.app` は **`case app(AppExport.Document, skipped: Int)`**（契約 §1.2 は `app(AppExport.Document)`）。`pages(_:)` が捨てた数を返す必要があり、契約が `AppExport.Document` に持たせることを禁じているので、数は `Parsed` で運ぶ。X・U は `case .app(let doc, let skipped)` で受けている。
- `AppExport.encode` は `header + pages.map(pageText).joined(pageSeparator) + footer`（契約 §1.1 の「`jsonValue(...).serializedData(pretty: true) + "\n"`」とは 0 ページのときだけ違い、`"pages": [\n\n  ]` になる。1 ページ以上なら整形の木と同一。書き出しは 0 ページを `nothingToExport` にするので実際には出ない）。
- `AppExport.parse(json:)` は `pages` が配列でないときも `notAnExport`（契約は流し読みの側にだけ書いていた。両方の道で結果を揃えるため）。
- `InkImport.parse` は `pages` が `[` で始まるのに `arrayElements` が切り分けられないとき（末尾のカンマなど）は投げずに全体解析に落とす（OS の `JSONSerialization` の寛容さに関わらず `AppExport.parse(json: JSONValue.parse(data))` と同じ結果になる）。読まない未知のトップレベルの鍵も `autoreleasepool` の中で解析して捨てる（壊れていれば両方の道で `invalidJSON`。検証者の直し、+2 項目）。
- `topLevelMembers` はエスケープのある鍵も JSON 文字列として読む（契約の「単純な文字列だけ」の上位互換）。BOM・末尾のごみ・末尾のカンマ・引用符の無い鍵は nil（全体解析が誤りを報告）。
- `exportedAt` / `app` が無いか文字列でなければ `""`。`parse(json:)` はページの順序を文書のまま保つ（pageId 順にするのは書き手 `InkPageStore.allPageIds()` の責務）。
- §1.1 の例の `"deleted": { … }` は 1 行で書いてあるが §1.3 の規則（object は 1 鍵 1 行）が優先で 3 行になる。数値以外を含む配列は 1 要素 1 行（数値だけの `pts` が 1 行）。
- KitChecks は +264（契約の見込み +180〜220 より多い）。`jsonFileName` は `safeFileName` を通さない（契約が名指すのは PDF だけ。JSON の名前に `/` `:` `\` は入らない）。
- 重複するトップレベルの鍵は契約どおり「後の方」（流し読み）だが、全体解析の `JSONSerialization` はこの macOS では最初の方を採る（RFC 8259 では重複は不正。書き手は作らない）。変えるなら `InkImport.swift` の `members[key] = …` を「最初が勝つ」に。

書き出し（X）:

- 日ページの「終日」ラベルは契約 §1.4 の「日付行（…「終日」ラベルだけ）」でなく、週と同じく **終日帯の gutter に 1 回**（画面の `AllDayBandView` と同じ）。日の 40 pt の日付行は時間軸の色と罫線だけ。高さの式は不変。日付行に入れるなら `PDFPageRenderer.drawDayDateRow` の `PaperText.drawLine` 1 行。
- 終日帯のバーの y は `bandPad / 2 + lane × laneStep`（上に 3 pt の余白。画面と同じ）。帯の高さは不変。帯・日付行・月と年の行は画面と同じ列の色（今日・週末）と 1 pt の区切り線も描き、年の今月はアクセント色、曜日と日付は semibold（契約は無言）。
- `testPDFRendersEveryKind` の「バイト単位で等しい」は、CoreGraphics が毎回書く `/CreationDate`・`/ModDate`・trailer の `/ID` を伏せたうえで等しい（それ以外の全バイトと長さは同一）。
- `Task.detached` はキャンセルを継承しないので、`exportJSON` は `withTaskCancellationHandler` で待ち、`onCancel` で作業を取り消す。`exportPDF` は `BandMigration.migrate(page)` を渡す（冪等）。`defaultDirectory()` / `appText` は `nonisolated static`。`appText` は両方の鍵が無いときだけ "ios/—"（片方なら "ios/<短い版 or —> (<ビルド or —>)"）。`FileManager.createFile` が false のときの `writeFailed` の文は「ファイルを作成できません: <ファイル名>」。
- `testPDFHasOnePageAndOverviewSize` の祝日名は `layout.dateLabels[].holidayName` から（テストターゲットの依存に `Holidays` の product が無いため）。
- 大きなファイルの実測は X が docs/M6.md に書く（契約の統合の順番）とあるが、§0 の所有に従って X の報告から C が §3 に写した。

画面（U）:

- `runExport(_ exportKind:)`（内部の名前。`kind` だと `exportPDF(kind:)` に渡すページの `kind` と被る）。進行の報告は `Task.isCancelled` か `exportPhase` が `.building` でなければ無視、終了後に `Task.isCancelled` なら `exportPhase` に触らない、PDF の道は 50 ms の後に `Task.checkCancellation`、`closeExportSheet` は `exportTask` を取り消す（見える挙動は契約どおり）。
- `.failed` の文は `Color.red`。`.choose` の「閉じる」はツールバーだけ。`byteText` の KB は切り捨て（1,535 → 「1 KB」）、MB は小数 1 桁（1 GiB → 「1024.0 MB」）。`pdfNote` の種類名は `AppExport.kindLabel`。`testParseM4Sheets` の中で `export` を確かめる（別のテストは足していない）。

規約類（L・W）:

### 5.2 実機でしか確かめられないこと

- **`swift test` とシミュレータのテストは CI でだけ**走る。手元では K・X・U のテストを XCTest の代役を実行する形で走らせた（§2.2）が、PencilKit のラスタの中身・`Bundle.main`・時間は本物の環境で変わりうる。
- **共有シート**（`ShareLink`）: iPad でボタンを anchor にした popover が出ること、iPhone で下から出ること、AirDrop・「ファイルに保存」・メールが並ぶこと、キャンセルしてもう一度「共有…」できること（§2.3 の 6・9）。
- **PDF の見え方**（§2.3 の 3・4）: 手書きが画面と同じ位置・太さ、週・日の終日帯のバーの横位置、祝日名、現在時刻の線が無いこと、「ファイル」アプリと Mac のプレビューで開けること。行が大きく伸びた月（`PaperSpec.monthRowMax`）や年では `InkSnapshot` の 12M 画素の上限で手書きの実効倍率が 2 未満に下がる（紙と文字はベクタのまま）。
- **PDF 作成中のスピナー**: `exportPDF` は MainActor で同期（この Mac で 0.2〜0.9 秒）。50 ms 待ってから呼ぶが、遅い端末で `.building` が描かれる前に終わる・固まって見えることがありうる。
- **大きな書き出し**（数十 MB）の所要と常駐メモリ（§3 はこの Mac と CI のシミュレータ）。背面に回しても続くこと（§2.3 の 8）。
- `openExport` の `saveNow()` が設定シートの上がっている間に同期で保存すること（ページが汚れているときだけ。ページを離れるときと同じ経路）。

### 5.3 動作上の注意

- 書き出しのファイルは tmp（`TegakiCalendarExport`）に置き、**次の書き出しの最初に前回の分を消す**。シートを閉じたときには消さない（AirDrop やメールが非同期に読んでいる途中のファイルを消さないため。残っても OS が掃除する）。
- **取り込み（復元）は購読中だけ**（M6-5。閲覧専用では「Web 版の手書きを取り込む」がペイウォールを出す）。書き出しは閲覧専用でも使える。
- 復元は「足す」方向だけ: 同じファイルを二度取り込んでも二重にならず、書き出した後にアプリで消した線は取り込み直しても戻らない（墓標が勝つ）。全部を元に戻すときは「この iPad の手書きを全て消す」の後に取り込む（SUPPORT の FAQ）。
- データファイルには各線の `dev`（端末のランダムな識別子）が入る（PRIVACY §4）。
- 取り込みファイルの目安は「おおむね 200 MB（手書き数万本）まで」（M6-26）。
- `ExportBuilder.appText` は `Bundle.main` の値（TestFlight では "ios/1.0 (N)"）。写真モードの JSON の書き出しは `nothingToExport`（ストアが空）。

### 5.4 技術的な注記

- 言語モードは Swift 5・並行性チェックは minimal のまま。`Export/*` → `InkModel`・`Layout`・`Paper/*`・`Ink/InkSnapshot`・`Persistence/InkPageStore`。`Views/*` → `Export/*`。`Sync/*`・`Ink/*`・`Paper/*`・レイアウトエンジンは触っていない（`PaperRenderer.draw` の `view:` にはダミーの `PaperView(content:)` を渡す。0-4）。
- `exportJSON` の `Task.detached` には値だけを渡す（`InkPageStore` / `InkPage` は Sendable）。`progress` は `@MainActor` のクロージャで、minimal では `@Sendable` が要らない（strict にしたら要る）。
- `InkImport.Scanner`（入れ子の struct）は `InkImport` の中だけで `Foundation.Scanner` を隠す（無害）。
- PDF の文字は埋め込みフォント、手書きは 1 枚の画像 XObject（SMask つき）。CoreGraphics が `/CreationDate`・`/ModDate`・`/ID` を毎回書くので、同じ内容でもバイト列は毎回少し違う。
- この Mac には Xcode が無いので、本番のコンパイルは CI。手元では TegakiKit の `swift build` / `KitChecks`、全ファイルの `swiftc -parse`、アプリ全体の Catalyst SDK に対する型検査、XCTest の代役に対するテストの型検査と実行まで（§2.2）。
