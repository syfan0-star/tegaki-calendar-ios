### 2.5 Sandbox での確かめ方（Apple の手順）

[Testing age assurance in sandbox](https://developer.apple.com/documentation/storekit/testing-age-assurance-in-sandbox) と Q&A による:

1. 端末の**デベロッパモード**をオンにする（Xcode につないだ端末で出る設定）。
2. 「設定」›「デベロッパ」›「Sandbox Apple Account」でサンドボックスのアカウントにサインイン。
3. アカウント › Manage › **Age Assurance** で場面を選ぶ（13 歳未満・13〜15・16〜17（親が重要な変更を断った）・18 以上で確かめていない・18 以上で確かめた、など 6 つ）。選ぶと Declared Age Range がその値を返す。**Revoke App Consent** で同意の取り消しもまねられる。
4. iOS・iPadOS 26.2 以上。

開発者フォーラムでの Apple の答え（[823635](https://developer.apple.com/forums/thread/823635)）: Sandbox の場面は**テキサス州だけ**で、州ごとの再現はしない。**TestFlight の版は、端末が Sandbox のアカウントにサインインしていなければ本番の環境を使う**。

このアプリでの意味: 旗のある場面（テキサス州）は Sandbox でしか作れず、それにはデベロッパモード（Xcode につないだ端末で出る設定）とサンドボックスのアカウント（作るのは本人の Connect の操作）が要ります。Apple の文書は Connect で場面を設定する道も書いていますが、端末にサンドボックスのアカウントで入るにはデベロッパの設定が要る見込みです【未確認】。この Mac には Xcode が入っていません（Mac の App Store から入れることはできる見込み。入れるか、iPad をつないでデベロッパモードにするかは本人が決める）。**1.2.2 では Sandbox の確かめはしません**（本人の決定 (b) の「要る作業」からの外れ。§10 の 21）。代わりに、旗の読み取りだけを「要る」に替えた、審査に出さない確かめ用のビルドで、Apple の画面が出て、閉じた後もアプリが普通に動くことを本人の iPad で見ます（§6.4、§8 の 0）。`requestAgeRange` は世界中で使え、法律の無い地域では本人が断れるためです（§2.2）。

## 3. 設計

### 3.1 いつ・どこで

**起動ごとに 1 回**（アプリのプロセスが始まるたび）。最初の「落ち着いた時」に、Apple の旗を読み、旗があればシステムの画面を 1 回だけ出します。

**落ち着いた時**（`AgeAssurance.canAskNow`。全部そろったとき）:

| 条件 | 見る値 |
| --- | --- |
| アプリが前面 | `UIApplication.shared.applicationState == .active` |
| 初回案内が済んだ | `onboardingDone` |
| 何も出ていない（設定・予定・取り込み・書き出し・初回案内・購入画面、それに年齢の画面そのもの） | `sheetIsUp`（`ageRangeAsking` を足す） |
| アカウントの質問が出ていない | `showAccountChange` |
| 「保存に失敗しました」が出ていない | `saveError != nil` |
| 初めての起動の購入画面を出すかが決まった | `firstPaywallPending`（新しい） |
| 画面の下の短い知らせ（トースト。ピンチの案内・週の始まりの知らせなど）が出ていない | `toast != nil`（評価のお願いの `reviewCanShowNow` と同じ） |
| 書いた直後ではない（最後に書き足してから 3 秒。`AgeAssurance.quietAfterInk`。評価のお願いの `ReviewPrompt.quietAfterInk` と同じ 3 秒） | `lastInkChangeAt` |

**呼ぶ所**（どれも同じ関数 `askAgeRangeIfDue()`。走っている間と、この起動で済んだ後は何もしない）: `appear()` の最後、`.active` になったとき、`sheetsChanged()` で何も出ていなくなったとき、アカウントの質問が閉じたとき、トーストが変わったとき（消えたとき）、`scheduleFirstLaunchPaywall` の判断が済んだとき。書いた直後で止まったときは 3 秒後にもう一度（書き終わりを知らせる所がほかに無いため。書き続けている間は待ち続ける）。`appear()` より前の `.active` では動かない（`appeared` を見る）。実装の後のレビュー（2026-11-08）で、「保存に失敗しました」が閉じたときと、アカウントの質問に答えたとき（2 つ目の「消しますか」の答えも）を足しました（§12.2 のずれ 6・7）。

**画面を出す直前に 1 秒待ち**（`AgeAssurance.settle`）、もう一度「落ち着いた時」かを確かめます。その間に何か出ていたら出さず、次の落ち着いた時にもう一度（旗は読み直さない）。

**初めての起動**: 初回案内（その中でカレンダーの許可）→ 購入画面を出すかの判断（`sheetGap` と、最初の更新を最大 3 秒待つ）→ 購入画面が出たら閉じるまで待つ → そこで年齢の段。初回案内とも購入画面とも重なりません。

**写真モード・XCTest のアプリ（テストの入れ物）・UI テスト（写真モードで動く）では、旗も読まず、何も呼びません**（`nextStep` が最初に止める）。TestFlight と審査の版では**呼びます**（評価のお願いと違う所。Apple の審査と Sandbox で働くように。日本のアカウントなら旗が無いので何も出ない）。

なぜ起動ごとか（§10 の 1）: 何も保存しないで済む（「入れたときに 1 回」は「聞いた」を端末に残すことになる）。Apple の文書は、断った人が「もう一度共有」を選ぶと「アプリを次に開いたときにアプリがまた聞く」と書いている。年齢の区分は誕生日で変わる。出すかどうかはシステムが決め、答えはシステムが宣言の記念日まで覚える（§2.2）ので、決めた人に毎回出るのではない見込み（毎回出ないかは【未確認】、§11）。前面に戻るたび（`.active` のたび）にはしない（同じ起動の中で何度も聞かない）。

### 3.2 純粋な決まり（TegakiKit）

新しいファイル `TegakiKit/Sources/Access/AgeAssurance.swift`。`Access` はアプリがもう使っているモジュールなので、`Package.swift`・`project.yml` の直しは要りません。レビューの前の形（`canAskNow` の値が 6 つ、KitChecks 285 件）をリポジトリの外の写しの木に入れて、`swift build` と KitChecks が通ることを確かめました（§12.1）。2026-11-07 のレビューで `quietAfterInk` と `canAskNow` の 2 つの値を足した今の形（§6.1 の 478 件）は、写しの木で走らせ直していません（担当が §6.5 で確かめる）。

```swift
// 1.2.2 (docs/R1_2_2.md §3): whether to ask the system for the person's age range (Apple's Declared Age
// Range), and when. Pure: the app reads Apple's regulatory flag and shows the system's own sheet
// (Sources/TegakiCalendar/Views/AgeRangeAsker.swift); this file only says what comes next. Nothing is
// stored: the state is one launch's, kept in memory by the app.
import Foundation

public enum AgeAssurance {
    /// The three ages that give the four categories of the US state laws (under 13, 13–15, 16–17,
    /// 18 and over; Texas Business & Commerce Code §121.021(b)). Where a law asks, Apple replaces them
    /// with the region's own; elsewhere the app never asks.
    public static let ageGates = [13, 16, 18]
    /// Seconds from a calm moment to the system sheet; `canAskNow` is asked again after them.
    public static let settle: Double = 1
    /// Seconds without new ink before the sheet may come (the same 3 s as `ReviewPrompt.quietAfterInk`),
    /// so it never cuts into a pen stroke.
    public static let quietAfterInk: Double = 3

    /// The device's OS in the three bands of docs/R1_2_2.md §2.6.
    public enum Band: Equatable, Sendable {
        /// iOS / iPadOS 17.0 – 26.1: no API says whether a law applies to this person, so never ask.
        case noRegionCheck
        /// 26.2 – 26.3: `AgeRangeService.isEligibleForAgeFeatures`.
        case eligibility
        /// 26.4 and later: `AgeRangeService.requiredRegulatoryFeatures` contains `.declaredAgeRangeRequired`.
        case regulatoryFeatures
    }

    /// What the system said about this person in this launch.
    public enum Signal: Equatable, Sendable {
        /// Not read yet in this launch.
        case notRead
        /// A law asks for the age range (the flag is there / eligible is true).
        case required
        /// No law asks (the flag is missing / eligible is false).
        case notRequired
        /// The read failed (notAvailable, a network error, …): nothing in this launch.
        case unreadable
    }

    /// Why nothing more happens in this launch. `mac`: an iPad app on a Mac or on Apple Vision Pro (§2.6).
    public enum Reason: Equatable, Sendable {
        case screenshotMode, testHost, mac, askedThisLaunch, oldSystem, notRequired, unreadable
    }

    public enum Step: Equatable, Sendable {
        case stop(Reason)
        case readRegulatoryFeatures
        case readEligibility
        case requestAgeRange
    }

    /// `ProcessInfo.operatingSystemVersion`'s major and minor → the band.
    public static func band(major: Int, minor: Int) -> Band {
        if major > 26 || (major == 26 && minor >= 4) { return .regulatoryFeatures }
        if major == 26 && minor >= 2 { return .eligibility }
        return .noRegionCheck
    }

    /// The next step of this launch. The app runs it until `.stop`: read the flag of the band, then ask
    /// only when the flag says a law requires it, once.
    public static func nextStep(band: Band, signal: Signal, askedThisLaunch: Bool,
                                screenshot: Bool, testHost: Bool, onMac: Bool) -> Step {
        if screenshot { return .stop(.screenshotMode) }
        if testHost { return .stop(.testHost) }
        if onMac { return .stop(.mac) }
        if askedThisLaunch { return .stop(.askedThisLaunch) }
        switch (band, signal) {
        case (.noRegionCheck, _): return .stop(.oldSystem)
        case (.eligibility, .notRead): return .readEligibility
        case (.regulatoryFeatures, .notRead): return .readRegulatoryFeatures
        case (_, .required): return .requestAgeRange
        case (_, .notRequired): return .stop(.notRequired)
        case (_, .unreadable): return .stop(.unreadable)
        }
    }

    /// The screen is calm enough for the system sheet: in front, past the first-time guide, nothing of
    /// ours up (a sheet, the account question, the save-failed alert, a toast), the first-launch paywall
    /// decided and no ink in the last `quietAfterInk` seconds.
    public static func canAskNow(active: Bool, onboardingDone: Bool, sheetIsUp: Bool, accountQuestion: Bool,
                                 saveFailed: Bool, firstPaywallPending: Bool, toastShowing: Bool,
                                 inkRecently: Bool) -> Bool {
        active && onboardingDone && !sheetIsUp && !accountQuestion && !saveFailed && !firstPaywallPending
            && !toastShowing && !inkRecently
    }
}
```

### 3.5 保存も送信もしない

- UserDefaults・iCloud・ファイルに何も書きません。新しいキーは 0。
- この起動の旗（要る・要らない）と「聞いたか」は、メモリの中の値（`AgeRangeAsker` の static）だけで、アプリが終われば消えます。答えそのものは関数の中で捨て、どこにも置きません。
- ログにも何も書きません（写真モードの `store:` のような行も足さない）。
- 通信: アプリは何も送りません。旗と画面は iOS・iPadOS の仕組みで、Apple との通信があるとしてもアプリのものではありません（それでもプライバシーポリシーは、「だけ」と書いた通信の相手の一覧から漏れないように言葉を足す。§5.1）。
- プライバシーマニフェスト（`PrivacyInfo.xcprivacy`）は変えません（DeclaredAgeRange は理由の申告が要る API ではない）。

### 3.6 画面と使いやすさ

- アプリの画面は 1 点も変わりません。新しい字は 0（`tools/l10n` の L-3 の ja の基準 516 字のまま）。
- 出るのは Apple の画面だけで、言葉・VoiceOver・文字の大きさは iOS・iPadOS が受け持ちます。
- その画面が出ているかもしれない間は `sheetIsUp` が true なので、アカウントの質問・週の始まりの知らせ・ピンチの案内・評価のお願いは待ちます。アプリが上に何かを重ねることはありません。
- 逆に、トースト（ピンチの案内・週の始まりの知らせ）が出ている間と、書いた直後（3 秒）は、年齢の画面の方が待ちます（§3.1）。ピンチの案内は出た時に「出した」と記録されるので、上に重ねると見られないまま使い切られる。書いている線も切らない。

### 3.7 評価のお願い（1.2.1）との関係: 同時には出ない

- `scheduleReviewRequest` の最初の guard に `AgeRangeAsker.finished` を足す。**この起動の年齢の段が済むまで、評価のお願いは予約もしない。**
- 年齢の画面が出ているかもしれない間は `sheetIsUp` が true なので、予約済みのお願いも `reviewCanShowNow` で止まる（`reviewCanShowNow` の形と 64 通りのテストは変えない）。
- 年齢の段は済んだら同じ起動の中で二度と動かないので、評価のお願いの後に年齢の画面が出ることもない。
- そもそも評価のお願いは TestFlight と審査の版では呼ばない（1.2.1 の決まり）。

### 3.8 コードの形

**新しいファイル `Sources/TegakiCalendar/Views/AgeRangeAsker.swift`**（`import DeclaredAgeRange` はこのファイルだけ。1.2.1 の `ReviewRequester.swift` が StoreKit を閉じ込めたのと同じ考え）:

```swift
import Access
import UIKit
#if canImport(DeclaredAgeRange)
import DeclaredAgeRange
#endif

/// 1.2.2 (docs/R1_2_2.md §3): Apple's Declared Age Range, the minimum. Reads Apple's regulatory flag for
/// this person and, only where it says a law requires it, asks with the system's own sheet. The answer
/// is never looked at, kept or sent, and nothing on the screen changes. `CalendarRootScreen.askAgeRangeIfDue`
/// decides when (`AgeAssurance.canAskNow`) and runs `AgeAssurance.nextStep`; this is the only file of the
/// app that imports DeclaredAgeRange (iOS 26), behind `#if canImport` and `#available`, so iOS 17–26.1 never
/// touch it (the framework is weak-linked, project.yml).
@MainActor
enum AgeRangeAsker {
    /// This launch's state (docs/R1_2_2.md §3.5). Nothing is stored: the next launch starts again.
    static var signal: AgeAssurance.Signal = .notRead
    static var askedThisLaunch = false
    /// The steps of this launch reached `.stop` (the rating prompt waits for it, §3.7).
    static var finished = false

    /// The OS band of this device (§2.6).
    static var band: AgeAssurance.Band {
        let version = ProcessInfo.processInfo.operatingSystemVersion
        return AgeAssurance.band(major: version.majorVersion, minor: version.minorVersion)
    }

    /// An iPad app on a Mac ("Designed for iPad") or on Apple Vision Pro: Apple's flag is never set on a
    /// Mac, and DeclaredAgeRange is unavailable on visionOS (§2.6).
    static var onMac: Bool {
        if ProcessInfo.processInfo.isiOSAppOnMac { return true }
        if #available(iOS 26.1, *) { return ProcessInfo.processInfo.isiOSAppOnVision }
        return false
    }

    /// The view controller the system's sheet was asked over (weak). `sheetIsGone` looks at it (§3.4).
    static weak var shownOver: UIViewController?

    /// Nothing is presented over `shownOver` any more (or it is gone): the sheet is not up, whether or not
    /// Apple's call has returned. Looked at on the return to the foreground (§3.8).
    static var sheetIsGone: Bool { shownOver?.presentedViewController == nil }

    /// `.readRegulatoryFeatures` / `.readEligibility` → the signal. Any error → `.unreadable` (§3.4).
    static func read(_ step: AgeAssurance.Step) async -> AgeAssurance.Signal {
        #if AGE_FORCE
        // The check build only (testflight.yml `age_force`, docs/R1_2_2.md §6.4; never submitted): the flag
        // is taken as set, so Apple's sheet comes up on any account on iOS / iPadOS 26.2 or later.
        if step == .readRegulatoryFeatures || step == .readEligibility { return .required }
        #endif
        #if canImport(DeclaredAgeRange)
        switch step {
        case .readRegulatoryFeatures:
            if #available(iOS 26.4, *) {
                do {
                    let features = try await AgeRangeService.shared.requiredRegulatoryFeatures
                    return features.contains(.declaredAgeRangeRequired) ? .required : .notRequired
                } catch {
                    return .unreadable
                }
            }
        case .readEligibility:
            if #available(iOS 26.2, *) {
                do {
                    return try await AgeRangeService.shared.isEligibleForAgeFeatures ? .required : .notRequired
                } catch {
                    return .unreadable
                }
            }
        case .stop, .requestAgeRange:
            break
        }
        #endif
        return .unreadable
    }

    /// The system's sheet over `anchor`. Shared, declined, cancelled or an error: all the same, nothing
    /// changes (§3.4). The response is dropped here without being looked at.
    static func request(in anchor: UIViewController) async {
        shownOver = anchor
        #if canImport(DeclaredAgeRange)
        if #available(iOS 26.0, *) {
            let gates = AgeAssurance.ageGates
            _ = try? await AgeRangeService.shared.requestAgeRange(ageGates: gates[0], gates[1], gates[2], in: anchor)
        }
        #endif
    }

    /// The view controller on top of the window in front (the system presents its sheet over it).
    static func anchor() -> UIViewController? {
        let scenes = UIApplication.shared.connectedScenes.compactMap { $0 as? UIWindowScene }
        guard let scene = scenes.first(where: { $0.activationState == .foregroundActive }) else { return nil }
        var top = (scene.windows.first(where: \.isKeyWindow) ?? scene.windows.first)?.rootViewController
        while let presented = top?.presentedViewController { top = presented }
```

```swift
// MARK: - The age range (1.2.2, docs/R1_2_2.md §3)

/// At a calm moment of this launch (`AgeAssurance.canAskNow`), the steps of `AgeAssurance.nextStep`:
/// read Apple's flag, and only where it says a law requires it, the system's sheet, once. Nothing in
/// screenshot mode, the XCTest host, on a Mac or Apple Vision Pro, or on iOS 17.0–26.1. Called from
/// `appear`, `.active`, `sheetsChanged`, the account question's close, a toast's change, the first-launch
/// paywall's decision and the wait after fresh ink.
private func askAgeRangeIfDue() {
    guard appeared, ageRangeTask == nil, !AgeRangeAsker.finished else { return }
    guard canAskAgeRangeNow else {
        askAgeRangeAfterInkIfWriting()
        return
    }
    ageRangeTask = Task { @MainActor in
        defer { ageRangeTask = nil }
        while true {
            let step = AgeAssurance.nextStep(band: AgeRangeAsker.band, signal: AgeRangeAsker.signal,
                                             askedThisLaunch: AgeRangeAsker.askedThisLaunch,
                                             screenshot: ScreenshotMode.isActive, testHost: SyncEngine.isTestHost,
                                             onMac: AgeRangeAsker.onMac)
            switch step {
            case .stop:
                AgeRangeAsker.finished = true
                return
            case .readRegulatoryFeatures, .readEligibility:
                AgeRangeAsker.signal = await AgeRangeAsker.read(step)
            case .requestAgeRange:
                try? await Task.sleep(for: .seconds(AgeAssurance.settle))
                // Something came up in the meantime: not asked; the next calm moment tries again (fresh ink
                // has no such moment, so it looks again `quietAfterInk` later).
                guard canAskAgeRangeNow, let anchor = AgeRangeAsker.anchor() else {
                    askAgeRangeAfterInkIfWriting()
                    return
                }
                AgeRangeAsker.askedThisLaunch = true
                ageRangeAsking = true
                await AgeRangeAsker.request(in: anchor)
                ageRangeAsking = false
            }
        }
    }
}

/// Fresh ink is the one wait that no other moment ends (the pen just stops): look again `quietAfterInk`
/// seconds later, and again while the person keeps writing. One wait at a time; the flag is not read again.
private func askAgeRangeAfterInkIfWriting() {
    guard ageRangeInkWait == nil, ageRangeInkIsRecent else { return }
    ageRangeInkWait = Task { @MainActor in
        try? await Task.sleep(for: .seconds(AgeAssurance.quietAfterInk))
        ageRangeInkWait = nil
        askAgeRangeIfDue()
    }
}

private var ageRangeInkIsRecent: Bool {
    lastInkChangeAt.map { Date().timeIntervalSince($0) < AgeAssurance.quietAfterInk } ?? false
}

private var canAskAgeRangeNow: Bool {
    AgeAssurance.canAskNow(active: UIApplication.shared.applicationState == .active, onboardingDone: onboardingDone,
                           sheetIsUp: sheetIsUp, accountQuestion: showAccountChange, saveFailed: saveError != nil,
                           firstPaywallPending: firstPaywallPending, toastShowing: toast != nil,
                           inkRecently: ageRangeInkIsRecent)
}
```

### 5.3 テキサス州 §121.053（重要な変更の前に App Store に知らせる）は当たるか

- 条文（[SB 2420](https://capitol.texas.gov/tlodocs/89R/billtext/html/SB02420F.htm)、2026-11-07 に読み直した）: 開発者は、**利用規約かプライバシーポリシーの重要な変更**の前に、配っている App Store に知らせる（(a)）。重要なのは、(1) **開発者が**集める・保存する・人に渡す個人データの種類を変える、(2) 年齢区分（§121.052）やその元の中身を変える、(3) 課金や広告を足す、(4) 機能や使い勝手を大きく変える、のどれか（(b)）。US_AGE_LAWS.md §2 のまとめと同じです。
- Claude の読み（法律の助言ではありません）: **当たらない**と読みます。(1) 開発者が集める・保存する・人に渡す物は 1.2.2 でも無い（区分は端末の中で受け取って捨て、開発者のところへは届かない）。ただし条文（§121.055(b)）は、App Store が渡す年齢の情報を「開発者に渡される個人データ」と書いているので、「開発者に届かない」は Apple の App Privacy の定義での言い方で、条文の言葉でも同じと言えるかは確かではない。足す文は、法律が求める受け取りを書くだけ。(2) 4+ のまま。(3) 課金・広告は足さない。(4) 旗のある人に、起動ごとに 1 回まで Apple の画面が出ることがある（毎回出るかは Apple しだい。§11）が、アプリの画面と機能は同じ。
- なので **App Store への知らせ（と PermissionKit の Significant Change）は出しません**。US_AGE_LAWS.md §5 (a) の専門家に聞く案を取るなら、ここも聞く点に入れる（§11）。

### 5.4 App Privacy は「データの収集なし」のまま

Apple の定義（[App privacy details](https://developer.apple.com/app-store/app-privacy-details/)）では、「収集」はデータを端末の外へ送り、その場の処理に要るより長く開発者や第三者が使える状態にすることで、**端末の中だけで扱うデータは収集に当たらず、答える必要も無い**とされています。年齢の区分は端末の中で受け取って、見ずに捨てるので、収集に当たりません（US_AGE_LAWS.md §5 (b) と同じ結論）。
