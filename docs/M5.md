ブランチ `m5`。`main` への取り込みはリード（本人）が行います。版はアプリ **0.6.0**。

本人の決定どおり（契約の冒頭）: サブスクリプション（買い切りではない）／月 300 円・年 2,400 円・14 日間無料／閲覧専用では予定の作成・編集も止める（B-4）／規約・プライバシー・サポートは Web 版の Pages の `app/` に置く（B-6、0-2）／日本中心・EU 除外／Small Business Program に申し込む。リードの決定 D1〜D8 はそのまま実装し、照合で加わった M5-27〜M5-38 も全部そのとおり（ずれは §5.1）。

## 3. StoreKitTest の可否（契約 §7.3.3 の判定）

**結論: `SKTestSession` のテスト（`StoreKitSessionTests` の 7 本）は CI では 1 本も走っていない。** ファイルは既定でコンパイルされる（`#if STOREKIT_TEST` には退いていない）が、GitHub の macOS ランナー（macos-26、Xcode 26.6、iOS 26.5 のシミュレータ）では StoreKit のテスト環境そのものが壊れているので、`setUp` の判定で 7 本とも `XCTSkip` になる。完了の根拠は契約 §7.3.3 の退き先と同じで、偽物に対する `StoreModelTests` の 26 本（§7.3.2 の 22 本 + 4 本。221 本の中で全部通っている）。

経過:

1. 1 回目（run 38958098578、06615bc）: 7 本中 6 本が赤。`SKTestSession(configurationFileNamed: "Products")` の init は成功し、`Product.products` は 2 商品（正しい ID、導入オファー付き）を返した — **`.storekit` の形式は正しく読めている**（§7.1 の「鍵名を合わせる」直しは不要だった）。しかしログに `[SKTestSession] Error saving configuration file: Error Domain=SKInternalErrorDomain Code=3` と、`clearTransactions` / `resetToDefaultState` / `storefront = "JPN"` / `locale = ja_JP` の書き込みが全部同じ Code=3 で拒まれた行。その結果 storefront が USA のままで価格が `$1.99` / `$14.99`（`testConfigurationLoadsBothProducts` は 300 を期待して赤）、`session.buyProduct` は `StoreKitError.notEntitled`（他の 5 本）。待ち時間の問題ではない（買えないので Transaction は永久に来ない）。同じ症状の報告: Apple Developer Forums 830493 / 836842（Xcode 26.3〜26.6 のシミュレータ。コードのコメント参照）。
2. 1 回目の直し（413e8a9）: `setUp` の最後に `skipUnlessTheTestEnvironmentWorks()` — `Storefront.current?.countryCode` が 3 秒以内に JPN になるか、月額の `Product.price` が 300 なら続行、どちらも駄目なら理由付きの `XCTSkip`。契約の「.storekit の形式と待ち時間を直す」の代わり（§5.1）。
3. 2 回目（run 38965068987、413e8a9）: 7 本とも `skipped`（各 3.1 秒、`testBuyingMonthlyStartsATrial` だけ 5.6 秒）。skip の文言は 7 本とも「SKTestSession's storefront stayed USA, monthly price 1.99」、Code=3 の行は 49 行。赤ではないので §7.3.3 の「2 回目も同じ理由で赤なら `#if STOREKIT_TEST`」には進んでいない。3 回目（run 38977743922）も同じ（§2.1）。

走っていないので分からないこと: §7.3.1 の 7 本の期待値（試用 13〜15 日、期限切れ → `.expired`、返金 → `.revoked`、試用後の資格 false、`Transaction.updates` だけで権利が付く、clearTransactions 後の復元）は本物の StoreKit に対しては未確認。**`testRefundRevokes` の `store-test: refund route = …` も出ていない**（1〜3 回目のログに 0 行）ので、返金が規則 1（`Transaction.updates` の写し）と規則 7（`renewals` の `state == .revoked`）のどちらで捉えられるかは不明。これらは §2.3 のサンドボックス試験（4・6・7。返金は Connect からは起こせないので 12 の「購入履歴を消去」が代わり）と、Xcode のある Mac での `xcodebuild test`（§4.2 のリードの 4）で確かめる。

`#if STOREKIT_TEST` でなく `XCTSkip` にした理由: 既定でコンパイルされるので、`SKTestSession` の API の使い方（`buyProduct(identifier:)` の async 版、`refundTransaction(identifier: UInt)`、`expireSubscription(productIdentifier:)`、`disableDialogs` / `storefront` / `locale` …）は本物の StoreKitTest.framework に対してコンパイラが確かめている（この Mac の Catalyst SDK には StoreKitTest が無く、手元では代役に対する型検査まで。§2.2）。環境が直ったランナーや手元の Xcode では何もしなくても 7 本が走る。退くときは `project.yml` の `TegakiCalendarTests` の `SWIFT_ACTIVE_COMPILATION_CONDITIONS` の口（コメント）に `STOREKIT_TEST` を足し、ファイル全体を `#if STOREKIT_TEST` で囲む。

- `renewalDate` は iOS 18 以降だけなので、iOS 17 の端末では「次回更新」の日付が Transaction の期限（= 更新日）になる。同じ日付になるはずだが実機で確認。
- ペイウォールの提示のタイミング（設定・編集シートを閉じて 0.35 秒後。`importWeb` と同じ技法）、購入のトースト（シートが閉じる動きの最中に出て 3 秒残る）、`UILongPressGestureRecognizer(minimumPressDuration: 0, pencil のみ)` が PencilKit の描画認識器を無効にした状態で `.began` を報告すること（CI のテストは delegate の答えと認識器の設定まで）、`.manageSubscriptionsSheet`（iOS 17 の API。Catalyst の StoreKit に対する型検査まで）。
- ペイウォールのシートの高さ: iOS 18 以降の iPad の縦向きは CI の 13 インチの写真で確認（§4.1）。横向きの 11 インチ（高さ 834 pt）で `ViewThatFits` が `ScrollView` に切り替わって末尾まで届くこと、iOS 17 の iPad の標準のフォームシートで EULA の行と末尾の「あとで」までスクロールできること（先頭の「あとで」は見えている）、価格の行や結果の 1 行が増えたときにシートの高さが追従すること（追従しなくても ScrollView に切り替わるので切れはしない）。
- 「指でも書く」オンで閲覧専用のとき、指が紙に触れても何も出ないこと（認識器は Pencil だけ。設計どおり）。
- 価格の記号: 写真・見本は U+00A5「¥」、実機の `displayPrice` は ja_JP の ICU で全角「￥」(U+FFE5) になりうる。テストは数字だけで比べている。
- 控えの 3 日の猶予（M5-30）: 機内モードで更新日をまたぐ実験（§2.3 の 8 の変形）。

### 5.3 動作上の注意

- **初回起動がオフラインで控えも無い**と「確認中（閲覧専用）」（M5-26）。回線が戻って前面復帰すれば正しくなる。ペイウォールは自動では出ない。
- **初回ペイウォールが出ない条件**（M5-33）: 最初の確認が 3 秒で終わらない、App Store に届かない、価格が取れない。この場合フラグは立たず次の起動でもう一度判定する。購読者には出さずフラグだけ立てる。
- **アプリを開いたまま期限をまたぐ**と次の前面復帰まで書ける（M5-9。タイマーで監視しない）。
- **無料試用 → 有料の最初の請求に失敗**すると猶予が無く即「お支払いに問題（閲覧専用）」（M5-3。規約第 5 条 5 項とサポート FAQ に明記）。
- **写真モードの価格は固定**（¥300 / ¥2,400 / ¥200）。実機の記号は全角になりうる（§5.2）。
- `Product.products` は 1 時間に 1 回まで（M5-38）。価格が変わっても最長 1 時間は前の表示。ペイウォールの「再読み込み」は `offers` が空のときだけ出る。
- 設定 › 購入 からの復元の結果は、設定が上がっている間は脚注に出る（トーストではない）。
- 閲覧専用で投げなわ／予定ツールを選ぼうとするとトースト（道具は変わらない）。既に投げなわを持っていて閲覧専用に変わると道具が最後のペンに戻り、選択が解除される。

### 5.4 技術的な注記

- 言語モードは Swift 5・並行性チェックは minimal のまま。`Access` は Foundation だけ（`DayKit` にも依存しない）。`Store/*` → `Access`、`Views/*` → `Store/*` と `Access`。
- `Transaction.offerType`（iOS 17.2 で非推奨）は `#available(iOS 17.2, *)` の else 側だけで使う。配信対象 17.0 では警告にもならないはず（Xcode 26 が警告を出しても `project.yml` に警告をエラーにする設定は無い）。
- 名前の衝突: `Sources/TegakiCalendar/Calendar/EventKitService.swift` に入れ子の `enum AccessState`（カレンダーの許可）が既にある。`EventKitService` の中では修飾なしの `AccessState` はそちらなので、必要なら `Access.AccessState` と書く。モジュールのトップレベルでは `import Access` の後の `AccessState` は購読のほう。
- `LegalLinks` は `URL.appending(path:)`（iOS 16+）。パッケージは iOS 17 / macOS 14。
- `PaywallSheet` の `ViewThatFits` は iOS 16+、`.presentationSizing(.form.fitted(…))` は iOS 18+（`#available(iOS 18.0, *)` で分岐。iOS 17 の iPad は標準のフォームシート）。`.manageSubscriptionsSheet` と `.onChange` / `.onDisappear` は `ViewThatFits` に付けている（NavigationStack は無い）。
- `StoreModel.make` の XCTest ホストの分岐は `SyncEngine.isTestHost`（M4 から）を使う。ホストが `CalendarRootScreen` を出すと `scheduleFirstLaunchPaywall` が見本の購読者で `paywallShownAfterOnboarding = true` をホストの UserDefaults に書くことがある（無害。`AppSettingsTests` は別 suite）。
- `StoreSnapshot.storeReachable` は `products` か `renewals` の結果でだけ変わる（契約の定義どおり）。初回の `refresh` では必ず `products` が走るので `scheduleFirstLaunchPaywall` が読む値は新しい。
- この Mac には Xcode が無いので、本番のコンパイルは CI。手元では TegakiKit の `swift build` / `KitChecks`、全ファイルの `swiftc -parse`、アプリ全体の Catalyst SDK に対する型検査、XCTest と StoreKitTest の代役に対するテストの型検査まで（§2.2）。
